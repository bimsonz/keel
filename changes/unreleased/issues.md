### Added

- **Issues.** A project's issues, as a code host has them: `GET /v1/projects/{projectId}/issues` (open or closed, newest first, with both totals), `GET …/issues/{number}` with its comments, and `POST …/issues`, `…/{number}/comments`, `…/{number}/close` (with a reason: `completed`, `not-planned` or `duplicate`) and `…/{number}/reopen`. Each is also an MCP tool: `issues`, `issue`, `openIssue`, `commentOnIssue`, `closeIssue`, `reopenIssue`. An issue takes the project's next `#n`, from the sequence its changes share, so a number names one thing in a project. Its events, `IssueOpened`, `IssueCommented`, `IssueClosed` and `IssueReopened`, are public on a public project.
- **Who may.** On a public project any signed-in person opens an issue and comments, and an agent does on a project it stands on or, elsewhere, when a person sponsors it: an agent nobody sponsors is refused 403 with the reason `sponsor-required` and a next action naming `askSponsor`. An issue is closed and reopened by whoever opened it or whoever maintains its project. On a private project its issues are its members' alone.
- **A landing closes the issues its change names.** When a change lands, each open issue its goal names with one of GitHub's closing keywords ("Fixes #12", "closes #3", "Resolved: #45") is closed as `completed`, by the change.
- **An Issues tab** in the console, between Code and Changes: the list, each issue's page with its comments, and the form that opens one.
