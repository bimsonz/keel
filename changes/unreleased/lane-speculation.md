### Changed

- **A lane verifies the batches behind the one in flight at once, and offers trunk each only after every batch ahead of it has landed** (no route).
  - **Forming behind.** While the batch in flight verifies and a KeelVerify box is free, the lane forms the next batch behind the last. It is composed on that batch's candidate, with every member ahead as its `predecessors` and the lane's `chainEpoch`, then bundled and started at once. Depth isn't capped: it is bounded by the free boxes and the queue.
  - **Verdicts.** A verdict for a batch behind is kept on the lane until every batch ahead has landed. Promotion fast-forwards trunk to a candidate's own tip, so the next batch's base is then trunk's head, and trunk is offered only the batch in flight. If trunk moved otherwise, it declines the batch and the lane verifies it again.
  - **Cancelling.** Any failure cancels the batch and every batch behind it: a batch ahead that does not land, or a batch behind that is refused or whose step fails. Each is invalidated (`CandidateInvalidated` gains reason `cancelled` and `because?: BatchId`, the batch whose failure undid it), its KeelVerify instance is stopped, and its members requeue blamed for nothing. The Candidate machine takes a new `Cancel` command from forming, assembled, verifying or green.
  - **Additive contracts:** `BatchVerification.capacity(): Effect<{ free }>`, which the Workflow adapter answers unbounded until KeelVerify's box count is read; the Lane's state gains `behind?` and `chainEpoch?`; and a batch in flight gains `on?` and `kept?`.
  - **Behind the batch in flight**, a batch is composed in GitCore alone (`CandidateRequest.gitcoreOnly`), so a conflict there cancels it in seconds rather than after MergeBox's cold box, which held the lane's step, and a green head's promotion, for minutes. Once a batch has failed behind a batch in flight on its own, nothing more forms behind that one (`Lane.heldBehind`); the changes form in flight, where every tier runs.
