### Added

- **`GET /v1/changes/{changeId}/diff` (MCP `diff`): what a change alters, file by file with its hunks**, as a code host's "Files changed" shows a pull request. A change not yet landed is read from its own workspace, from its base to the commit it submitted; a landed change is its commit on trunk against the commit before it. Each file has its `status` (`added`, `modified`, `deleted` or `renamed`, a same-content move with `previousPath`), `additions` and `deletions`, and its hunks with three lines of context, each line numbered on the side or sides it is on. A binary file is `binary` and one past the inline caps or the line diff's edit limit is `tooLarge`, both with no hunks. It is read as the change is, so anyone reads a public project's. A change that has submitted no commit, or ended without landing once its workspace was let go, is 404 `change.diff_unavailable` (a new problem code).
