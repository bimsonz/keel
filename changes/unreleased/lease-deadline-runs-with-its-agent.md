### Added

- **`LeaseRestarted {changeId, leaseId}`**, a change's event (`events.tsp`'s `KeelEvent`, the domain's catalogue, the console's reader and mock rules, `events.md`): committed with the hand-back of a change to its agent (`ChangeBounced`, `ChangeDrifted`) while its lease is Active, it starts the lease's 15 minutes again. Public, as `LeaseLapsed` is.
- **The agent holding a change's lease reads it back with the change**: `Change.lease?: ChangeLease {id, renewedAt, lapsesAt?}` on `GET /v1/changes/{id}` and MCP `change`, shown only to the change's own agent, under the change's run when it has one. `lapsesAt` is absent while Keel holds the change. A `change.lease_stale` refusal's next action, to read the change, now finds the lease.

### Changed

- **A lease's deadline runs only while its change waits on its agent.** While Keel holds the change (from Submitted through Integrating, or parked for a ruling) its lease cannot lapse, and handing the change back (Bounced, Drifted) starts the 15 minutes again. Keel's own queue and verification counted against the lease, so a change bounced after a long queue was parked in the same commit as its bounce, and its agent had to adopt it before it could rebase.
  - Core: `isLapsed` takes the change. A hand-back commits `LeaseRestarted` in the same transaction, and its fold sets `lease.renewedAt`, so a replay rebuilds the restart as it was decided and a log committed before the event existed keeps the deadlines it was decided under. The fold judges an adoption by the lease's own time rule (`deadlinePassed`), so a log decided under either rule folds. `decideChange`'s `Lapse` commits nothing outside an agent-owned state; a lease already recorded Lapsed while Keel held the change parks it at the hand-back, and `adopt` is refused in every state Keel holds, whatever the lease. `LeaseNotLapsed.lapsesAt` is optional: absent while Keel holds the change, when `adopt`'s 409 says to wait for the hand-back. The Change DO arms the deadline only in an agent-owned state.
  - A call that carries the change's lease and passes the lease check renews it, whatever it then answers: a refused `revise`, `rely`, `submit`, `rebase`, `commit` or lease-held `abandon` renews it, and so do `refreshWorkspaceToken` and `distinguish`, which passed the check and renewed nothing.
  - Docs: the Change and Lease tables, invariants and charts in `state-machines.md`, and `LeaseLapsed` in `events.md`.
- **A premise put in doubt by an edit says the footprint covers its anchor**: "`<chg>`'s footprint covers `<path>`, where `<symbol>` is anchored: the code your premise on `<subject>` rests on", or "…, the file your premise on `<subject>` rests on" for an anchor with no symbol. It said the change edits the path and named the symbol, as if the change had edited the symbol.
