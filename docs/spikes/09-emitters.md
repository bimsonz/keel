# S9: Emitters

Run on 2026-10-10 on the code that ships: `packages/spec`, `apps/keel/src/adapters/driving/{http,mcp}` and `apps/keel/src/generated/` (regenerated by `pnpm gen`).

## Answer

**GO on the fallback emitters: one handler object serves REST and MCP with no casts.**

The planned releases (`typespec-http-zod` 0.28, `typespec-hono` 0.25, `typespec-http-mcp` 0.2, `typespec-openapi-document` 0.6) were not on npm on 10 Oct; later that day npm still reported 0.27.0, 0.24.0, 0.1.0 and 0.5.0. Keel is pinned to those, with the workarounds listed in [AGENTS.md § TypeSpec](../../AGENTS.md#typespec).

| Criterion | Result |
|---|---|
| The same handler object serves one REST call and one tool call, with no casts | **Pass.** `makeHandlers(runner)` is passed unchanged to `registerRoutes` (typespec-hono) and `registerTools` (typespec-http-mcp). `pnpm typecheck` is green with no `as` at the seam |
| REST body equals the tool's `structuredContent` | **Pass in the pool** (`whoami.test.ts`) and **live on staging** (`pnpm smoke`: equal for two fresh agents, unequal across them) |
| Stateless `/mcp` with a bearer token | **Pass.** `/mcp` sits behind `requireBearerAuth` with host and origin checks; `KEEL_HOST` must equal the real host or `/mcp` answers 403. Protocol `2026-07-28` needs `mcp-method`/`mcp-name` headers and `_meta` on every request |
| problem+json responses | **Pass.** Declared error models map exhaustively at compile time; `c6-unmapped-error-tag` (a new tag with no mapping) fails `pnpm typecheck` |
| `tools/list` filtered by scope | **Pass** (pool `contract.test.ts`) |
| A negotiated (shared) route | **Not exercised.** http-mcp 0.1 was built against hono 0.23: no `@cookie` and no negotiated `@sharedRoute`. It moves in with the upgrade |

## Fallback consequences

- Separate output directories: `generated/http`, `generated/mcp`.
- No `Http.File` bodies, a plain `int32` `retry-after`, and optional response fields are omitted rather than set to `undefined`.
- No SSE in the spec: `@typespec/streams` is capped at 0.86 by http-zod 0.27, so `/v1/events` is a long-poll in the spec and SSE stays a non-spec route.
- Per-operation scopes: the OAuth flow model lists no scopes, and each operation passes its scope as `OAuth2Auth`'s second argument, because a flow's scopes override the operation's and every operation would demand all four.

## Emitter issues reported upstream

- `typespec-openapi-document` writes a wrong relative import when the output path contains `..`, so it emits into `packages/contracts/src`.
- The generated runtime files fail `erasableSyntaxOnly` and `noPropertyAccessFromIndexSignature`, so the apps that compile them leave those two flags off.

## Follow-up

Upgrading to 0.28/0.25/0.2/0.6 follows once they are published. Nothing on the critical path waits for it.
