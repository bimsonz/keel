# Changelog

Keel's contracts: the public API (`packages/spec`, emitted to `packages/contracts/openapi.json`), the MFP schema it imports, the ports in `packages/core/src/application/ports`, the DO RPC contracts in `apps/*/src/rpc`, and the runner protocol in `packages/runner-protocol`.

From `contracts-v0` on, every contract change gets a line here. Contract changes are additive (a new operation, an optional field, a new port or RPC method); a breaking change is listed under **Changed (breaking)** and says what a caller must do.

- `EscalationRaised` carries `options: EscalationOption[]` (`{id, label, consequence}`) in place of `options[]` and `consequences[]`, plus `category` (`EscalationCategory`), `evidence: EscalationEvidence[]` (`{class, summary, ref?}`), `precedents: decisionId[]` and `default` (an option id). `RulingGiven.option` is an option id (non-empty). `DecisionRecorded` gains `option` (the chosen id) and `summary` (its label). Reshaped in place: nothing commits these events yet. `EscalationNotFound` gains `nextActions`.
- `ProjectRpc.putSettings(command: PutSettingsCommand)` replaces `putSettings(projectId, settings)`, so the Project DO can audit who changed what (nothing called it).
- `TrunkAdvanced` carries `landings: MemberLanding[]` (`{changeId, commitSha, candidateId, proofId}`, one per member in group order) in place of `members[]` and `proofIds[]`, whose lengths differed (one proof per batch), so a member's Change DO could not land from them. `PromotionComposed` gains `commits: MemberCommit[]` (`{changeId, commitSha}`): each member's commit in the composed chain, which the landing carries; the Promotion machine's `Composed` takes them and refuses a chain that is not exactly the group's members, in order, with `CompositionMismatch` (new). The Change machine's `Land` takes the landing's `commitSha`, so `ChangeLanded.commitSha` is the commit on trunk, not the one submitted. Corrected in place: no Trunk DO has committed either event yet. Emitters set `TrunkAdvanced`'s `affected` to each landing's change.
- `EventRecord.payload` is a `KeelEvent` instead of `Record<unknown>`.
- `ChangeRpc.planCompiled` also commits `ChangeQueued {changeId, laneId}` in the same transaction, on the project's lane `lane:<projectId>:main`, and subscribes that lane there to `ChangeQueued`, `ChangeRequeued`, `ChangeWithdrawn` and `ChangeSuperseded` (ChangeQueued alone before); it answers the change Queued, where it answered it Verifying. No step comes between the plan and the queue.
- `listEvents` always answers `nextCursor`: the cursor just after the last item returned, even on the last page. `EventPage` is its own model rather than `Page<EventRecord>`, whose cursor is absent on the last page.
- `DerivedEffect` is Keel's derivation record, a union over `method`: `ExtractedEffect` (`extractor`, a ruling, no `p`), `DecisionModelEffect` (`clef`, opinion, `p` required in [0, 1]) and `CodeModelEffect` (`code-model`, opinion, `p?` in [0, 1]), each with at least one anchor. No derived effect is proof or testimony: an extractor executes nothing, and a `p` given with one is dropped at decode (no `EffectsDerived` is committed yet). The spec's `EventDerivedEffect` is the same union (`EventExtractedEffect`, `EventDecisionModelEffect`, `EventCodeModelEffect`), so the generated validator refuses a `clef` effect without `p`.
- Every number in the domain's wire schemas is `Schema.Finite`, refusing NaN and ±Infinity at decode: `InstantSchema`, `Proposition.value`, `PlanCompiled.costEstimate`, the memory `Tenet.value` and `TenetEstablished.value`, `VerificationPlan.costEstimate`, `StepResult.durationMs`, and the new gate masses and thresholds. `InvalidProbeCost.cost` is optional: present when the refused cost was finite.
- `TrunkWriter.push(from, to)` also fails `PackTooLarge`: the verified candidate is relayed byte for byte from staging, and a pack over the receive-pack cap lands nothing and bounces the promotion. `PushRejected.reason` is `stale` (trunk no longer held `from`) or `busy` (no callers).
- `CandidateComposer.compose(request)` takes a `CandidateRequest {candidateId, staging, base, at, members: CandidateMember[]}` (each member `{changeId, repo, base, head, author, title}`) and answers `ComposedCandidate {treeSha, commitSha, commits, ref, composer, tier, tierReason}`: the batch is restacked as one commit per member, chained in batch order (Change-Id trailer, the agent as author, Keel as committer at BatchFormed's time), and pushed to `refs/heads/cand/<candidateId>` in staging. `ComposedTree` is gone (no callers).
- `CreateProjectRequest.source` is required: the core-namespace repo trunk is forked from (the operation had no implementation).
- The identity use-case `enrolAgent(principal, input)` runs over the `Enrolments` port; its stub took `(request)` over `AgentDirectory | Ids | Clock` and had no callers.
- `admit` (probe admission) requires every complete run to fail in `A-noop` as well; a run is complete only once that cell is in. A pass or `n/a` there is non-discriminating, and a probe whose template cannot build an A-noop world is never admitted (spike S26).
- The flow grammar's `worlds(over)` and `StepSpec.worlds` are typed `FlowWorld` (`trunk|A|B|AB`), so no flow step can be scheduled in `A-noop`. `ProbeState` moved from `conflict.ts` to `probe.ts`, exported from the same index.
- The submission status operation is an MCP tool: `@tag("mcp")` with `@operationId("status")`. Its operationId was `Submissions_getSubmission` (an unused rename), so an agent over MCP can wait on its own submission.
- `ChangeCodecs.declare` answers `{change, preflight, grant: WorkspaceGrant}` and fails with `ChangeStateRefused | PoolExhausted | SketchNotFound`, because the Change DO takes its workspace before it decides (unused since contracts-v0).
- `CodeHost.create` and `fork` fail `RepoAlreadyExists {repo}` (new, in the ports) when the name is taken, leaving that repo as it was. It was a defect. The Artifacts adapter maps `ALREADY_EXISTS`, or through wrangler's proxy (which drops `code`) the message `repo already exists`, seen live on keel-ws-00. `createProject` treats one from a concurrent bootstrap as already done.
- `WorkspacePool.release(projectId, workspaceId, reason?)` names the project, as `grant` does, so the RPC adapter can address `pool:<projectId>` (no callers).
- The coordination use-cases `declare`, `revise`, `submit`, `abandon`, `adopt` and `getChange` are the Change DO's: they take the change id and the decoded Change RPC command, and carry exactly the ports and errors they use (`submit` needs `CodeHost`; `declare` no longer names `SubjectRegistry`). `declare` answers `{change, preflight, grant}`. `DeclareInput`, `SubmitInput` and `Declared` stay as the `Changes` port's inputs, and `rely`, `nearby` and `openSketch` stay stubs (unused since contracts-v0).

### Removed

- `SubjectRpc.rely` and its codec: a change relies on a subject through its own Change DO only (`ChangeRpc.rely`), which subscribes the subject.
- `LaneRpc.enqueue` and `LaneCodecs.enqueue`, which nothing called: a change joins its lane by its ChangeQueued only (no callers).

## contracts-v0 (10 Oct 2026)

Changes since `contracts-v0-rc1` (`3e7c7f1`, 10 Oct 2026). Everything is additive or a fix except the `EventOutbox` reshape, which landed before the freeze.

### Added

- `AgentDirectory.verifyCredential(clientId, secret)`: the adapter hashes and compares in constant time, so a client secret never leaves it.
- `declaredEffects?: MFP.Proposition[]` on declaring and revising a change. Advisory only: Keel derives effects from the diff.
- Kernel: pure content hashing (`ContentHash`, `sha256:` + 64 hex) and glob matching.
- Identity: every agent is enrolled in exactly one project. `Agent.projectId`, `Principal.projectId`, the token's `prj` claim, `AgentEnrolled.projectId`, the D1 column `agents.project_id` (migration 0002) and `projectId` on the API's `AgentProfile`.
- Ports `Changes` (the isolate's gateway to the Change DOs: `declare`, `submit`, `get`, `awaitSubmission`) and `Inbox` (`read`, long-polling), each with an in-memory adapter.
- Change RPC `submission(waitMs)`, answering `SubmissionStatus {change, commitSha}`; AgentSession RPC `reserveChange({idempotencyKey, fingerprint})` (a declare retried with the same key reaches the same change; the same key with another body is `IdempotencyConflict`) and `inbox({cursor, waitMs})`.
- Identity domain: `IdempotencyConflict`, and the `AgentNotice` and `InboxPage` schemas (the `Notifier` port re-exports `AgentNotice`, unchanged in shape).
- `CodeHost.diffTrees(repo, base, head)`: the leaves that differ between two commits, as `git diff-tree -r --no-renames` reports them, as `TreeChange` rows in bytewise path order. Unchanged subtrees are skipped by id.
- `CodeHost.delete(repo)`: idempotent. Workspaces are collected by deleting their repo.
- `CodeHost.info(repo)`: `{remote, defaultBranch}`. The remote's host carries the account id, so it goes only to a grant's holder and is never logged.
- `WorkspaceGrant.baseSha` and `WorkspaceGranted.baseSha`: the workspace's head at grant time, which is the change's base. Precheck diffs against it, so a mirror that lags trunk can't leave the base missing.
- WorkspacePool: `grant` is idempotent per holder; a retry returns the same workspace with a freshly minted token. `release(workspaceId, reason?)` takes the `WorkspaceCollected` reason (`landed`, `withdrawn` or `expired`; `withdrawn` when absent). The RPC gains `configure({source, target})` and `status()`.
- `commit()` in the ports: read the clock, then in one `EntityStore` transaction either return what the cause already committed or run the decision and append its events (gap-free `seq` per entity, dedupe keys `<kind>:<id>/<cause>/<type>#<n>`, `notified[]` from the subscription table at commit time). A refusal rolls back every write.
- `EventReceiverRpc.receive(envelopes)`: every Keel Durable Object receives events through this one method; `ChangeRpc`, `AgentSessionRpc` and the other DO contracts extend it. `DeliveryReceipt` and `EventCodecs` in `apps/keel/src/rpc/events.ts`.
- `CodeHostFixture` in `@keeltown/testing`: `commit(repo, ref, files)` and `scratch()`, provided by `makeCodeHostMemory().layer`. Tests seed repos through it, because `CodeHost` never writes git content.

### Fixed

- Scopes are per operation. Each operation now demands only its own scope; the OAuth flow model used to list all four, which overrode the operations and made every operation demand all of them.
- The Change RPC `submit` codec now carries submit's own errors, `ChangeNotFound | LeaseStale | ChangeStateRefused | CommitNotInWorkspace`. It had `RevisionMismatch`, which belongs to revise alone.

### Changed

- `EventOutbox` is reshaped around the outbox fan-out: `append(spec, at, drafts)`, `committed(entity, cause)`, `log(entity)`, `subscribe`, `unsubscribe`, `subscribers(type)` and `receive(dedupeKey, at)`, with its in-memory adapter on the in-memory `EntityStore` so one transaction covers both. It replaces rc1's `append`/`pending`/`acknowledge`.
- The MFP library is pinned at `github:bimsonz/mfp#v0.1.0-pre.3`.
- `CodeHost` reads fail with typed errors instead of dying: `RepoNotFound` (every read, `diffTrees`, `mintToken`, and `fork`'s source), `RefNotFound` (`head`), and `ObjectNotFound` (`readTree`, `readBlob`, and `diffTrees` when the repo lacks `base` or `head`). This narrows the error channels, but the port had no callers yet. Transport failures stay defects. `TreeEntry.type` gains `"commit"` for submodules, and `readTree` is documented as the commit's recursive listing.
- The in-memory `CodeHost` stores real git objects through gitcore. It fails `RepoNotFound` for a repo it never created or has deleted; it used to create the repo on the first read. Its `seed()` is replaced by `CodeHostFixture`.

## contracts-v0-rc1 (10 Oct 2026)

The interface freeze candidate: the TypeSpec spec and its OpenAPI document, the MFP schema v0, every port with an in-memory adapter and contract-suite stub, the use-case signatures, the DO RPC contracts with the Exit envelope, and the runner protocol v0.
